# 架构与诊断口径

`server.py` 使用 FastMCP 注册基础工具及新增工作流。`tools/workflow.py` 统一将异常转换为工具错误结果。stdio 日志写 stderr，工具结果通过 MCP 返回。

## 工程层

`project_inspector.py` 只读扫描工程，跳过版本控制、虚拟环境和符号链接目录。`.ioc` 提供 MCU 信息，`jlink-project.json` 提供明确覆盖值，编译数据库提供编译单元证据，ELF 提供实际链接符号。FreeRTOS 版本来自源头文件，不能证明烧录的每个字节属于该版本，结果中明确标记版本证据来源。

文件/工程数量有边界：最多 30000 个文件，单源码文本 2 MiB，固件 32 MiB。扫描不执行项目构建脚本。多个工程配置或固件无法唯一选择时返回候选和告警，不擅自按修改时间选取。

## 部署层

`firmware.py` 使用 pyelftools 和 intelhex，解析 ELF PT_LOAD 的物理加载地址、HEX 地址和明确 BIN 基址。当前允许 STM32 内部主 Flash 范围 0x08000000–0x09FFFFFF；具体可用容量仍由 J-Link 的准确器件算法决定。外部 Flash、选项字节、RAM 运行镜像、TrustZone 多镜像编排和多核部署需后续专项支持。

部署前校验镜像格式、范围、重叠和摘要。使用准确器件连接，拒绝通用 Cortex-M 模式烧录。写入后以 4096 字节块回读对比；任一失败不继续复位运行，并尝试暂停目标。未指定序列号且有多个探针时拒绝猜测。

## 硬件并发

`hardware_access.py` 提供重入事务锁和监控会话独占权。普通工具在完整操作范围持锁；后台工作线程携带会话 token 访问硬件，其他工具在监控期间拒绝操作。`get_runtime_report` 只读取缓存，不触碰 DLL。显式 `stop_runtime_monitor` 后释放 RTT 和独占权。

`firmware_watch.py` 是编译产物监听线程，稳定一秒后调用相同部署流程，每个哈希尝试一次。监听器仅可停止自己创建的监控会话。关闭服务器时先停止监听器，再停止监控器。

## 采集与分析

`runtime_monitor.py` 默认每 10 ms 排空一批 RTT，约每 500 ms 更新缓存报告。主机操作系统调度和 J-Link 带宽会影响实际频率，报告不能承诺硬实时采样。SystemView 的事件时间使用目标时间戳，主机时间仅用于消息顺序和采集生命周期。

增量解码器处理同步、标准无长度事件、带长度的扩展事件、U32 变长编码和特殊字符串长度。未知 OS/API 事件保留原始载荷。损坏后只在同步标记恢复。原始流最多 4 MiB；滚动分析窗口最多 20000 个事件。同步/丢包使上下文和 Ready 匹配失效。窗口截断后的首段状态未知，不向之前任务错误归属时间。

任务/ISR 是独占耗时，嵌套 IRQ 只归属最内层。Idle 与 unknown 分别统计。占比分母为观测到的完整事件窗口，不是主机等待时间。最近窗口内的活动未覆盖完整生命周期，不能用作长期实时性证明。

`runtime_diagnostics.py` 从匹配 Ready→Running 事件计算延迟，用可配置预算产生风险提示。ISR 占比同样只是预算超限提示。当前不推断完整互斥锁所有权，不证明死锁、饥饿或优先级反转。

默认 CPU 不停机，CPU 寄存器故障检查为 unknown。可选短暂停机检查活动异常及已支持内核的 SCB 故障状态，随后恢复原运行状态。CFSR/HFSR 为粘滞位，需要与活动异常和上下文结合解释，不自动清除故障位。

## 使用限制

主机不能恢复固件从未记录的历史。任务名、优先级、IRQ 及 Idle 信息取决于固件上报质量。线上的压缩 task ID 尚未分代处理，任务销毁后复用 ID 时可能合并统计。后台会话重启会替换上一份内存轨迹；需要保留时先 export_runtime_trace。

上游 GDB Server、设备补丁和可选语义检索继续保留。不要在后台监控时用其他进程连接同一 RTT 消费通道；本进程的独占权不能保护外部调试器。
